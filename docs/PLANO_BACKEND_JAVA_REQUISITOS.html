1. Visão Geral e Arquitetura do Sistema

1.1 Objetivo

Substituir a camada simulada (mock-api.ts) por uma API RESTful corporativa, resiliente, segura e auditável desenvolvida em Java 21 LTS e Spring Boot 3.3+, mantendo 100% de compatibilidade com o front-end React/TypeScript já existente.

1.2 Padrão Arquitetural de Software (Clean Layered Architecture)

A aplicação adota uma Arquitetura Limpa em Camadas (Layered Clean Architecture) com princípios de Domain-Driven Design (DDD) pragmático, garantindo baixo acoplamento, testabilidade e separação rigorosa de responsabilidades:

2.2 Catálogo Detalhado de Responsabilidade de Cada Classe

📦 Pacote config/ (Configurações do Framework)

- SecurityConfig.java: Configura o SecurityFilterChain do Spring Security 6. Define rotas públicas vs. autenticadas, desabilita CSRF (por ser API REST stateless com JWT), configura o DaoAuthenticationProvider, o BCryptPasswordEncoder(12) e a política de CORS. - CorsConfig.java: Configura as origens permitidas (allowed-origins), métodos HTTP (GET, POST, PUT, DELETE, OPTIONS) e liberação do envio de credenciais (cookies/tokens). - OpenApiConfig.java: Configura o OpenAPI 3.0 para geração da documentação Swagger em /swagger-ui.html. Inclui a definição do esquema de segurança bearerAuth (JWT). - RedisConfig.java: Cria o RedisTemplate com serializadores StringRedisSerializer para chaves e GenericJackson2JsonRedisSerializer para objetos JSON. - WebSocketConfig.java: Implementa WebSocketMessageBrokerConfigurer, habilitando o broker /topic (broadcast) e /queue (mensagens privadas por usuário /user), além do endpoint de handshake /ws. - JpaAuditingConfig.java: Habilita @EnableJpaAuditing para preenchimento automático de campos @CreatedDate e @LastModifiedDate nas entidades. - AsyncConfig.java: Habilita @EnableAsync utilizando o pool de Virtual Threads do Java 21 (Executors.newVirtualThreadPerTaskExecutor()).

📦 Pacote domain/model/ (Entidades de Banco de Dados JPA)

- Usuario.java: Representa a tabela tb_usuario. Contém id, nome, email, senhaHash, papel (Enum Papel), setor, telefone, localidade, podeCadastrarUsuarios, primeiroAcessoConcluido, ativo, criadoEm e a coleção @ElementCollection de setoresLiberados. - Chamado.java: Representa a tabela tb_chamado. Contém id, protocolo, titulo, descricao, status (Enum StatusChamado), prioridade (Enum PrioridadeChamado), setor, servico (@ManyToOne), solicitante (@ManyToOne), tecnico (@ManyToOne), filaSetor, @Version Long versao (concorrência otimista), slaAtendimentoHoras, slaResolucaoHoras, slaConsumidoMs, slaRodandoDesde, primeiraRespostaEm, oQueFoiFeito, resolvidoEm, motivoReabertura, avaliacao e coleções de comentários e histórico. - Comentario.java: Representa tb_comentario. Relaciona @ManyToOne com Chamado e Usuario (autor), contendo a mensagem, flag interno (nota técnica invisível ao solicitante) e data de criação. - HistoricoChamado.java: Representa tb_historico_chamado. Armazena imutavelmente cada mudança de status, assunção, encaminhamento ou devolução com tipo, descricao e autorNome. - ChamadoVinculo.java: Representa tb_chamado_vinculo. Mapeia associações entre chamados (chamadoOrigemId, chamadoDestinoId, tipo Enum TipoVinculo). - Servico.java: Representa tb_servico. Define itens do catálogo com nome, setor, prioridade, prazos de SLA e flag ativo. - SlaConfig.java: Representa tb_sla_config. Tabela paramétrica com os prazos padrão em horas por prioridade (baixa, media, alta, critica). - ConfigDominio.java: Representa tb_config_dominio. Lista os domínios aceitos pela instituição e define qual é o pré-selecionado (ehPadrao). - Auditoria.java: Representa tb_auditoria. Registra todas as ações do sistema com acao, detalhe, usuarioId, usuarioNome, ipOrigem e criadoEm. - Notificacao.java: Representa tb_notificacao. Alertas do usuário com usuarioId, chamadoId, tipo, mensagem e flag lida. - RecuperacaoSms.java: Representa tb_recuperacao_sms. Armazena o codigoHash (OTP de 6 dígitos), ticketValidacao, expiraEm, contador de tentativas e flag utilizado.

📦 Pacote dto/ (Records de Entrada e Saída)

📦 Pacote service/ (Casos de Uso e Lógica de Negócio)

- AuthServiceImpl.java: - login(): Autentica credenciais com AuthenticationManager, emite JWT e Refresh Token, grava auditoria auth.login. - refreshToken(): Valida o refresh token no Redis e emite novo par de tokens. - pausarChamado() & retomarChamado(): Congela/retoma a contagem de SLA atualizando slaConsumidoMs e slaRodandoDesde. - resolverChamado(): Valida o preenchimento obrigatório de oQueFoiFeito, altera status para resolvido, grava data de resolução e notifica o solicitante para avaliação. - devolverChamado(): Remove técnico atribuído, retorna chamado para filaSetor com justificativa e reativa contagem de SLA. - reabrirChamado(): Ação exclusiva de administradores/superusuários para reabrir chamado resolvido. - 📦 Pacote security/ (Componentes de Segurança)

- JwtService.java: Métodos generateToken(), generateRefreshToken(), extractUsername(), extractClaim(), isTokenValid(). Utiliza a biblioteca io.jsonwebtoken (JJWT 0.12.5). - JwtAuthenticationFilter.java: Intercepta toda requisição HTTP, extrai o header Authorization: Bearer , checa se o token está na lista negra do Redis, valida a assinatura e injeta o UsernamePasswordAuthenticationToken no SecurityContextHolder. - ChamadoSecurity.java: Bean @Component("chamadoSecurity") utilizado em anotações SpEL para validar em tempo de execução se o técnico possui permissão para atuar sobre o setor do chamado. - RateLimiterService.java: Implementa o algoritmo de Token Bucket utilizando comandos atômicos do Redis (INCR e EXPIRE) para mitigar ataques de força bruta.

3.1 Proteção Ativa Contra as Vulnerabilidades OWASP Top 10

Vulnerabilidade OWASPMitigação Implementada no Back-End Java
A01: Broken Access ControlVerificação de permissões em 2 camadas (SecurityFilterChain + @PreAuthorize com checagem de setoresLiberados no banco/JWT). Usuários comuns nunca acessam dados de outros solicitantes.
A02: Cryptographic FailuresSenhas hasheadas com BCryptPasswordEncoder (fator de custo 12). Tokens e códigos SMS armazenados como hash SHA-256 no banco e Redis. Conexões SSL/TLS 1.3 obrigatórias em trânsito.
A03: Injection (SQL & NoSQL)Utilização estrita de Spring Data JPA / Hibernate com Prepared Statements parametrizados. Não há concatenação de queries SQL nativas.
A03: Cross-Site Scripting (XSS)Sanitização de todos os campos de texto livre (descrições, comentários, justificativas) via OWASP Java HTML Sanitizer antes da persistência no PostgreSQL.
A04: Insecure Design & Brute ForceRate Limiting com algoritmo Token Bucket via Redis (máximo 5 tentativas de login por minuto por IP; máximo 3 tentativas de código SMS por telefone/usuário antes do bloqueio temporário).
A05: Security MisconfigurationHeaders de segurança HTTP ativados no SecurityConfig: X-Content-Type-Options: nosniff, X-Frame-Options: DENY, Content-Security-Policy, Strict-Transport-Security: max-age=31536000; includeSubDomains.
A07: Identification FailuresRecuperação de senha por SMS OTP com código numérico criptográfico de 6 dígitos, expiração estrita de 5 minutos e descarte imediato após o primeiro uso.
A08: Software & Data IntegrityValidação estrita de DTOs com Jakarta Bean Validation (@Valid, @NotNull, @Size, @Pattern). Concorrência otimista com @Version contra sobreescrita acidental de dados (lost updates).
A09: Security Logging & MonitoringTrilha de auditoria centralizada (tb_auditoria) gravando IP de origem, User-Agent, data/hora, autor e evento para todas as mutações cadastrais e de atendimento.
A10: Server-Side Request Forgery (SSRF)URLs externas de Gateway SMS e Webhooks validadas contra lista estrita de domínios confiáveis (whitelist).

7.2 Recomendação Prática

  • Recomendação Principal (Padrão Corporativo/Governamental):
  • - Dois repositórios Git independentes:
  • - ticket-hub-frontend (React + Vite + TypeScript + Tailwind)
  • - ticket-hub-backend (Java 21 + Spring Boot 3 + Maven)
  • - Vantagem: A equipe de front-end pode lançar melhorias de interface e correções visuais sem disparar a esteira do backend Java, e o backend pode aplicar patches de banco e segurança de forma independente.
  • Alternativa Válida (Monorepo Organizado):
  • - Se for mantido no mesmo repositório do Git, deve-se criar pastas irmãs de primeiro nível:
  • TEXT
         ticket-hub-sistema/
     ├── frontend/          # Todo o código React, Vite, package.json
     ├── backend/           # Todo o código Java, Spring Boot, pom.xml
     ├── docs/              # Especificações e PDFs de arquitetura
     ├── docker-compose.yml # Orquestração local de todos os serviços
     └── README.md
  • - ⚠️ Importante: Nunca crie o código Java dentro das pastas do React (src/ do front), pois isso mistura os ecossistemas, quebra ferramentas de análise estática e expõe arquivos de configuração do servidor.
